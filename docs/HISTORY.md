# Changelog

## 1.4 - 19 Sep 2026

- Derive a stable encryption key from Django `SECRET_KEY` by default, so
  cookieless session tokens survive process restarts.
- Add optional `COOKIELESS["CIPHER_KEY"]` support, accepting either a direct
  Fernet key or a shared passphrase that is deterministically derived.
- Add tests covering cipher-key derivation and override behavior.

## 1.3 - 19 Sep 2026

- Add Django 5.2 and Django 6.1 compatibility updates. [Ed Crewe]
- Replace deprecated decorator and middleware usage for modern Django.
  [Ed Crewe]
- Convert README to Markdown and update packaging metadata. [Ed Crewe]
- Add CI matrix for Python 3.12/Django 5.2 and Python 3.13/Django 6.1.
  [Ed Crewe]

## 1.2 - 26 Oct 2019

- Fix breach mitigation test for Python 3. [Ed Crewe]
- Fix test settings to correct path. [jonespm]
- Fix content length and decode. [C.Severance]

## 1.1 - 1 May 2019

- Rewrite for Python 3 and Django 2.2.
- Remove xteacrypt and use cryptography.

[Ed Crewe]

## 1.0 - 24 Feb 2014

- Test with latest Django 1.6.2.
- Enforce session keys as strings if the session fails to save, due to the
  move of the session serializer to JSON in Django 1.6.

[Ed Crewe]

## 0.9 - 18 Aug 2013

- Add protection against breach attack via nonce encryption,
  <http://breachattack.com/>.
- Add related test.

[Chris Bailey]

- Remove line return at end of session id introduced by base64 encoding.

[Ed Crewe]

## 0.8 - 4 Jan 2013

- Clean up some pylint.
- Switch to base64 encoding to shorten encrypted session IDs.

## 0.7 - 18 Dec 2012

- Add a `cookieless_signal` to allow custom code to be hooked to cookieless
  sessions.
- Pass a created flag for cookieless sessions to the signal.
- Add a `no_cookies` marker key to cookieless sessions for the same reason.
- Check automatic form rewrites to ensure sessions are not already set
  manually.
- Fix tests check of hidden `session_id` broken by extra space in hidden field.
- Add `post` method for test class view so test posts do not throw
  `HttpResponseNotAllowed`.
- Make the secret generated by settings options more unique.

## 0.6 - 21 Nov 2012

- Never use the cookie session for decorated views, since it may break sessions
  passed by cookieless means.

## 0.5 - 14 Nov 2012

- Only rewrite redirect URLs if `USE_GET` is true and it is the same domain.

## 0.4 - 9 Nov 2012

- Fix issue of not having `no_cookies` to test in `process_request` by getting
  it from url resolvers. Now we only check for cookie session where we should,
  and cookies cannot interfere with cookieless sessions.
- Make deletion of cookies that are passed on to the URL an optional feature.
- Use `settings.TESTING` based on argv to disable, instead of checking server
  name.

## 0.3 - 7 Nov 2012

- Turn off cookieless for Django test browser, since it is hard-coded to use
  dummy sessions if an alternative session provider is in use, otherwise
  cookieless could break other package tests.
- Add server-name switch to re-enable test browser for cookieless functional
  tests.
- Change anon user switch to `NO_COOKIE_PERSIST`, never use cookie-originated
  sessions, move to `process_response`.
- Make session use cookieless POST/GET over cookies when present.
- Delete request cookies if found in response.
- Refactor settings to a dictionary.
- Add tests.
- Move fix for non-unicode key to decrypt method.

[Ed Crewe]

## 0.2 - 6 Nov 2012

- Add `COOKIELESS_ANON_ONLY` setting to avoid cookieless for authorised users.
- Update example settings.
- Add test suite.
- Do not assume request `META` keys exist, so it works with test client.
- Fix session decrypt with wrong secret, generates non-unicode key bug rather
  than new session.
- Add `SPECIFIC_URL` option for extra security for sessions.

[Ed Crewe]

## 0.1 - 4 Nov 2012

- Initial release.
- Django snippets basis for middleware,
  <http://djangosnippets.org/snippets/1540/>.
- Add simple crypt of session ID when used in HTML.
- Call standard `contrib.sessions.Session` if not decorated as `no_cookies`.
- Add CSRF exempt decorator to ensure cookies are not set by that path.
- Add template tags for users who prefer manual adding of session IDs.
- Add settings options to configure level of security applied, for example
  whitelist of referrers and no URL rewriting.

[Ed Crewe, julio carlos and Ivscar (snippet), Paul Chakravarti (xteacrypt)]
